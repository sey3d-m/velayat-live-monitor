# پاسخ‌نما — فقط رابط آنلاین، متصل به دیدبان موجود

این افزونه نمایشی مستقل از موتور فعلی است و **هیچ تغییری در فایل `velayat_monitor.py`، مدل Gemini، Apps Script، Google Sheets یا بات بله نمی‌دهد**.

## چه چیزی در بسته افزوده شده؟

- `docs/index.html`: صفحه عمومی فارسی راست‌چین، جست‌وجو و فیلتر برنامه، بازکردن خلاصه پاسخ، آرشیو.
- `docs/overlay.html`: لایه شفاف مناسب Browser Source در OBS/vMix؛ نمایش چرخشی آخرین پرسش‌های منتشرشده.
- `docs/assets/*`: CSS و JavaScript بدون کلید API، بدون نیاز به سرور پویا.
- `docs/data/feed.json`: داده عمومی و **پاک‌سازی‌شده**. فایل اولیه خالی است.
- `publish_site_data.py`: تبدیل `program_report.json` دیدبان به JSON عمومی، بدون انتشار متن کامل، نام مخاطبان، اطلاعات داخلی و secrets.
- `.github/workflows/publish-dashboard.yml`: پس از اجرای **موفق** workflow اصلی دیدبان، artifact گزارش فارسی را دریافت، feed را به‌روز و سایت را در GitHub Pages منتشر می‌کند.

## راه‌اندازی اولیه (فقط یک‌بار)

1. محتویات ZIP را **در ریشه همان مخزن دیدبان موجود** کپی یا آپلود کنید. فایل‌های قبلی را حذف یا جایگزین نکنید.
2. در مخزن GitHub به `Settings → Pages → Build and deployment` بروید و **Source: GitHub Actions** را انتخاب کنید.
3. در `Settings → Actions → General → Workflow permissions` گزینه **Read and write permissions** را فعال کنید (برای ثبت فایل `feed.json` در مخزن؛ در برخی مخزن‌های سازمانی ممکن است ادمین باید مجوز بدهد).
4. در زبانه `Actions`، workflow تازه **Publish Q&A Dashboard** را با گزینه **Run workflow** یک‌بار دستی اجرا کنید تا سایت اولیه ساخته شود.
5. آدرس سایت شما معمولاً این است: `https://USERNAME.github.io/REPO-NAME/`؛ لینک دقیق را از `Settings → Pages` بخوانید.
6. برای مشاهده نسخه نمایشی با پرسش‌های ساختگی، `?demo=1` به آدرس صفحه اضافه کنید. در حالت عادی هیچ داده ساختگی نشان داده نمی‌شود.

بعد از هر اجرای **موفق برنامه فارسی** در workflow قبلی `Velayat Live Monitor`، workflow جدید به‌صورت خودکار اجرا می‌شود و `program_report.json` را از **Artifacts** خوانده و فقط اطلاعات عمومی لازم را منتشر می‌کند. هیچ کلید Gemini در رابط HTML قرار نمی‌گیرد.

## نکته بسیار مهم درباره «زنده» بودن

دیدبان فعلی، صدا را حین برنامه ضبط/تبدیل می‌کند اما پرسش‌ها و پاسخ‌های استخراج‌شده را **در انتهای برنامه** در `program_report.json` می‌گذارد. بنابراین این نسخه در همان لحظه پرسش را نمایش نمی‌دهد. پس از اتمام یک برنامه و انتشار GitHub Pages، داده‌ها ظاهر می‌شوند. برای نمایش چندثانیه‌ای حین برنامه، باید در آینده خروجی‌های میانی به دیدبان اضافه شود.

## خروجی تلویزیونی

صفحه `https://USERNAME.github.io/REPO-NAME/overlay.html` را به‌عنوان **Browser Source** در OBS/vMix استفاده کنید. توصیه: 1920×1080 با پس‌زمینه شفاف. کادر پاسخ در پایین/راست قرار می‌گیرد. به‌شکل خودکار هر ۱۴ ثانیه بین حداکثر ۶ پرسش اخیر جابه‌جا می‌شود. به‌منظور جلوگیری از نمایش اشتباه پاسخ قدیمی، اگر از زمان انتشار گزارش بیش از ۴ ساعت بگذرد، به وضعیت «در انتظار پاسخ تازه» می‌رود.

برای مشاهده نمای آزمایشی Overlay: `overlay.html?demo=1` (با واترمارک واضح «نمونه نمایشی»).

## حریم خصوصی و احتیاط

- در داده عمومی عمداً **نام مخاطب** منتشر نمی‌شود، حتی اگر دیدبان آن را شناسایی کرده باشد.
- محتوای منتشرشده خلاصه **هوش مصنوعی** است و نه نقل‌قول مستقیم تأییدشده از کارشناس.
- اگر تحلیل برنامه در دسترس نباشد یا گزارش معتبر فارسی نباشد، فایل عمومی تغییری نمی‌کند.
- فقط سؤال‌هایی منتشر می‌شوند که خود دیدبان در ساختار `audience_questions` آن‌ها را «پاسخ‌داده‌شده» تشخیص داده باشد. این ساختار **پرسش‌های بی‌پاسخ را تولید نمی‌کند**.
- مخزن عمومی به معنای عمومی‌بودن پرسش‌ها است. نام، تلفن و دیگر اطلاعات شخصی را در متن پرسش نیز بازبینی کنید؛ پاک‌سازی سیستماتیک متن هر نوع داده حساس هنوز تضمین نشده است.

## بازبینی فنی / عیب‌یابی

- نام workflow اصلی باید دقیقاً `Velayat Live Monitor` باشد؛ در فایل فعلی همین نام وجود دارد.
- Artifact باید فایل `program_report.json` داشته باشد و نام آن با `velayat-persian-` شروع شود؛ در فایل فعلی همین‌طور است.
- اگر Publish با خطای مجوز مواجه شد، سطح دسترسی Actions به مخزن، مجوز Pages و تنظیمات `github-pages` environment را بررسی کنید.
- اگر صفحه خالی بود، در Actions بررسی کنید آیا فایل `docs/data/feed.json` پس از نخستین اجرای موفق برنامه فارسی پر شده است یا نه.
- خطاهای انتشار روی GitHub Pages یا کمبود مجوز مانع عملکرد **موتور اصلی دیدبان** نمی‌شوند، زیرا publish workflow جداگانه است.

## تست محلی

از ریشه مخزن: `python -m http.server 8000 -d docs`؛ سپس آدرس `http://localhost:8000/?demo=1` را در مرورگر باز کنید. برای نمایش داده واقعی، به‌صورت پیش‌فرض صفحه از `docs/data/feed.json` استفاده می‌کند.
