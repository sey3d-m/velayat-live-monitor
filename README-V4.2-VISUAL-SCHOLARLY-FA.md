# دیدبان ۴.۲ آزمایشی — تصویر زنده و داوری علمی مستند

این تغییرات روی شاخه مستقل feature/visual-scholarly-review-20261019 اعمال شده است.
شاخه main دست‌نخورده است.

## قابلیت تصویری
- هم‌زمان با ضبط اصلی صوت، یک FFmpeg مستقل از همان URL زنده فریم JPEG می‌گیرد.
- فریم‌ها هر حدود ۶۵ ثانیه تا حداکثر ۱۰۰ عکس در برنامه تهیه می‌شوند؛ در پایان شش فریم با پراکندگی زمانی انتخاب می‌شود.
- هر عکس توسط Gemini از نظر آراستگی پوشش قابل مشاهده، چین‌خوردگی آشکار لباس، رنگ پوشش و دکور، نور و قاب تحلیل می‌شود.
- تحلیل نمی‌تواند از روی یک عکس ثابت گوینده را شناسایی کند. نقش «مجری» یا «کارشناس» فقط وقتی از زیرنویس یا شواهد واضح تصویری قابل احراز باشد درج می‌شود؛ در غیر این صورت «نامشخص».
- زمان فریم نسبت به شروع ضبط **تقریبی** است و الزاماً همان لحظه صحبت شخص نیست. این قابلیت جایگزین diarization یا تشخیص گفتار هم‌زمان با ویدیو نمی‌شود.
- عکس و توضیحات همراه آن از مسیر sendPhoto به همان chat_id بله ارسال می‌شود. تصاویر روی GitHub Pages عمومی نمی‌شوند و فقط روی runner تا پایان اجرای workflow باقی می‌مانند.
- در نبود ویدیوی زنده یا خطای Gemini، شکست تصویری مانع از ساخت گزارش صوتی نمی‌شود. با این حال اگر ارسال عکس ثبت‌شده در بله شکست بخورد، اجرا با خطای تحویل نشانه‌گذاری می‌شود.

## قابلیت علمی
- مدل اولیه، علاوه بر ایرادهای مشخص، فهرستی از ادعاهای دینی/تاریخی مهم را با تایم‌کد استخراج می‌کند.
- مرحله دوم با Gemini و ابزار Google Search درباره حداکثر ۳ ادعا (قابل تنظیم تا ۴) جست‌وجو و تحلیل جداگانه انجام می‌دهد.
- منابع پیشنهادی در دامنه‌های شیعی تعریف‌شده بررسی می‌شوند.
- **فقط وقتی** نشانی در grounding metadata باشد و عبارت نقل‌شده از متن HTML همان صفحه واقعاً بازیابی شود، برچسب «شاهد متنی بازیابی‌شده» ثبت می‌شود. این برچسب به معنی صحت سند حدیث، درستی استنباط یا تأیید قطعی همه ادعا نیست.
- اگر صفحه ۴۰۳ باشد، فقط PDF در دسترس باشد، جست‌وجو منبع قابل تطبیق ندهد، یا نقلِ مدل با متن منبع برابر نباشد، خروجی «بدون شاهد مستقل» می‌ماند. ارزیابی اولیه و پیشنهاد اصلاح نیز با این قید ارائه می‌شود، نه حکم قطعی.
- خروجی این بخش در پیام مستقل بله، program_report.json و payload ارسالی به Google Sheets قرار می‌گیرد. برای نمایش ستون‌ها در شیت احتمالاً باید گیرنده webhook نیز سازگار شود.
- این راستی‌آزمایی فعلاً فقط برای گزارش کامل فارسی فعال است.

## تنظیمات اختیاری GitHub

Settings → Secrets and variables → Actions → Variables:

| نام | مقدار پیش‌فرض | توضیح |
|---|---|---|
| ENABLE_VISUAL_REVIEW | true | ثبت و تحلیل تصویر؛ false برای غیرفعال |
| VISUAL_REVIEW_MODEL | gemini-3.8-flash | مدل چندوجهی |
| ENABLE_SCHOLARLY_REVIEW | true | بررسی ادعاهای برنامه فارسی |
| SCHOLARLY_REVIEW_MODEL | gemini-3.8-flash | مدل دارای Google Search |
| MAX_SCHOLARLY_CLAIMS | 3 | از ۱ تا ۴ |

همان Secrets قبلی GEMINI_API_KEY، BALE_BOT_TOKEN و BALE_CHAT_ID استفاده می‌شوند؛ توکن جدیدی لازم نیست.

## آزمون‌ها

در یک branch/PR:
- GitHub Actions → Validate visual and scholarly enhancements
- بررسی نحو Python + تست‌های بدون تماس با سرویس بیرونی.
- **آزمون واقعی هنوز لازم است:** برنامه زنده دارای ویدیو، دسترسی به Gemini 3.8 و Search، کیفیت عکس، زمان‌بندی، ارسال عکس بله و امکان بازیابی نقل‌قول از منابع شیعی باید در اجرای واقعی تأیید شود.
- اجرای آزمایشی ممکن است مصرف API و Grounding داشته باشد؛ رایگان بودن همه فراخوانی‌ها تضمین نمی‌شود.

برای بازگشت به حالت قبل شاخه اصلی را تغییر ندهید و PR را ادغام نکنید، یا پس از ادغام commit مربوط را revert کنید.
