# ربات سردبیر دیدبان ـ نسخه رایگان Cloudflare

**مستقل از Vercel، مستقل از رصد، گزارش، تقطیع و دوبله.** این پوشه فقط کد آماده اجرای ربات `@dideban_adminbot` است. هیچ سرویس پولی یا افزونه‌ای لازم نیست. استقرار و تنظیم دسترسی نیازمند حساب Cloudflare Free است؛ محدودیت‌های رایگان طبق مستندات Cloudflare اعمال می‌شوند.

## قبل از انتشار

- به فایل‌های اصلی `velayat_monitor.py`، Workflow اصلی و تقویم نوبت‌های ثابت دست نزنید.
- **Webhook را فعال نکنید و Polling را حذف نکنید** تا آزمون واقعی با توکن و حساب مدیر انجام شود.
- توکن گزارش‌دهی `BALE_BOT_TOKEN` را برای این ربات استفاده نکنید.
- فایل تقویم اصلی در GitHub فعلاً `config/didban_extra_programs.json` است؛ نسخه نمایشی آن `docs/data/extra-programs.json` است. هر دو در یک Commit عوض می‌شوند.

## راه‌اندازی از صفحه تنظیمات Cloudflare (رایگان)

1. در [Cloudflare Dashboard](https://dash.cloudflare.com/) طرح **Free** را انتخاب کنید. Workers & Pages → Create Worker. نام نمونه: `didban-bale-editor-free`. نیازی به خرید دامنه یا پلن Paid نیست.
2. در Storage & databases → D1 یک پایگاه‌داده با نام `didban-editor-state` بسازید و متن فایل `schema.sql` را از Console آن اجرا کنید.
3. در Worker → Settings → Bindings یک D1 binding با نام دقیق `DB` متصل کنید. Worker را با محتوای `worker.mjs` منتشر کنید؛ یا از Wrangler رایگان با فایل نمونه `wrangler.toml.example` استفاده کنید.
4. در Worker → Settings → Variables and Secrets این موارد را فقط در بخش **Encrypted Secrets** وارد کنید (هیچ‌کدام در GitHub یا فایل کد نوشته نشوند):
   - `BALE_EDITOR_BOT_TOKEN`: توکن اختصاصی ربات مدیر، جدا از ربات گزارش‌دهی؛
   - `EDITOR_ADMIN_IDS`: شناسه عددی مجاز بله (شناسه‌ها با ویرگول جدا شوند)؛
   - `GITHUB_TOKEN`: fine-grained GitHub PAT محدود به مخزن `sey3d-m/velayat-live-monitor` با فقط `Contents: Read and write`؛
   - `WEBHOOK_PATH_SECRET`: رشته تصادفی **حداقل ۳۲ کاراکتری**، جدا از توکن بله، ترجیحاً ۴۸ تا ۶۴ نویسه hex/base64url؛
   - `GITHUB_REPO`: مقدار عادی (غیرمحرمانه) `sey3d-m/velayat-live-monitor`؛ می‌توانید آن را به‌صورت متغیر معمولی ثبت کنید.
5. آدرس `https://YOUR-WORKER.workers.dev/health` فقط وجود سرویس/کامل‌بودن متغیرها را اعلام می‌کند. خروجی `configured` **به معنای اتصال واقعی بله یا GitHub نیست**.
6. تنها بعد از آزمون درخواست ساختگی معتبر، دستورهای واقعی، جلوگیری از تکرار و ثبت GitHub و داشتن نسخه برگشت، مهاجرت انجام شود: ابتدا **فقط مرحله `didban_calendar_bot.py poll` و پاسخ‌های مرتبط با آن** در Workflow `didban-extra-calendar-dispatch.yml` غیرفعال شوند؛ `extra_schedule.py due` و dispatch اجرای برنامه‌های اضافی باید حفظ شود. سپس دستور `setWebhook` برای **همان توکن ربات مدیر** با URL زیر اجرا شود:
   `https://YOUR-WORKER.workers.dev/bale/WEBHOOK_PATH_SECRET`
   توکن را **در گفتگو یا خروجی لاگ منتشر نکنید**. ثبت URL را با یک ابزار امن یا صفحه مدیریت بله انجام دهید، نه با گذاشتن آن در issue یا URL عمومی Github.
7. `getWebhookInfo` و دریافت واقعی `/start`، فهرست، ورود به فرم، دکمه‌ها و یک عملیات امن قابل بازگشت را در گفتگوی خصوصی آزمایش کنید. بعد از موفقیت واقعی می‌توانید مسیر قدیمی Polling ربات سردبیر را در یک Commit مستقل حذف کنید.

### نکات امنیتی و عملیات

- درخواست‌های ورودی باید دقیقاً به مسیر محرمانه برسند؛ هویت مدیر نیز از `message.from.id` در گفتگوی خصوصی بررسی می‌شود. پشتیبانی بله از header امضای webhook در منابع عمومی یکدست نیست؛ به **رشته محرمانه مسیر و allowlist** تکیه شده است.
- `update_id` در D1 یکتا است و خروجی پاسخ در صف پایدار می‌ماند. در خرابی ارسال بله، درخواست باید دوباره ارسال شود؛ امکان تکرار *پیام پاسخ* در فاصله بین ارسال و ذخیره وضعیت وجود دارد، اما تلاش شده تغییر تقویم تکراری ثبت نشود.
- تأیید تغییرات فقط پس از Commit معتبر GitHub است؛ در حالت شکست ارتباط GitHub، منوها با آخرین cache پاسخ می‌دهند اما ثبت برنامه متوقف می‌شود.
- تقویم فقط برنامه‌های اضافی را تغییر می‌دهد و قفل تداخل نوبت‌های ۱۸، ۱۹:۳۰ و ۲۱ را برای روزهای غیرجمعه حفظ می‌کند.
- هر سرویس رایگان محدودیت مصرف دارد؛ انباشت بسیار زیاد پیام/برنامه می‌تواند به سقف استفاده برسد. برای این ربات کوچک معمولاً کافی است، اما تضمین سرویس نامحدود رایگان وجود ندارد.

### بازگشت اضطراری

1. `deleteWebhook` را **فقط برای ربات مدیر** اجرا کنید؛ هرگز توکن گزارش/دوبله را تغییر ندهید.
2. گام Polling قدیمی **فقط ربات مدیر** را از نسخه پیش از cutover برگردانید؛ Cron اجرای برنامه‌های اضافی همچنان باقی است.
3. `getWebhookInfo` را برای اطمینان از خالی‌شدن URL بررسی و Polling دستی را آزمایش کنید.
4. به‌هیچ‌وجه فایل تقویم، گزارش، Clip یا دوبله قدیمی را پاک نکنید.

این مخزن کد و آزمون‌های آفلاین را ارائه می‌کند. تا زمانی که Worker و D1 در حساب واقعی مستقر و Webhook بله آزمایش نشده‌اند، **وضعیت عملیاتی ربات فوری = تأییدنشده**.
