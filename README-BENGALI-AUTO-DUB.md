# دوبله خودکار و فوری دیدبان به بنگالی

## وضعیت
شروع دوبله پس از ارسال موفق هر کلیپ فارسی طراحی شده است. انتشار واقعی بعد از ادغام در main و آزمون موفق تأیید می‌شود.

## مسیرها
- @live_vtv: کلیپ اصلی فارسی بدون تغییر
- @double_vtv: فقط نسخه دوبله‌شده صوتی بنگالی
- BALE_CHAT_ID: گزارش‌ها، تحلیل‌ها و اسناد اصلی بدون تغییر
- فقط دو کلیپ موفق اول هر برنامه به بنگالی دوبله می‌شوند؛ تعداد کلیپ‌های فارسی تغییر نمی‌کند.

## فرایند فوری
1. در پاسخ موفق sendVideo فارسی، enqueue_after_sent اجرا می‌شود.
2. فایل MP4 به محل امن موقت کپی و هم‌زمان آپلود Artifact روی GitHub شروع می‌شود.
3. بلافاصله پس از آپلود، repository_dispatch اجرا می‌شود.
4. Workflow مستقل Didban Bengali Auto Dubbing بدون انتظار برای کلیپ دوم یا پایان برنامه شروع می‌شود.
5. Faster-Whisper، M2M100-418M، مدل مرد بنگالی و FFmpeg پردازش را انجام می‌دهند.
6. فقط پس از بررسی نتیجه فایل به @double_vtv ارسال می‌شود.

شروع درخواست پردازش فوری است ولی اجرای Runner و پردازش CPU ممکن است طول بکشد.

## شرایط
- بات باید مدیر @double_vtv باشد (توسط مدیر کانال تأیید شده).
- ارسال دستی کلیپ به کانال فارسی رویداد دوبله را آغاز نمی‌کند؛ تنها کلیپ‌های تولیدشده توسط دیدبان.
- ابزارها API پولی نمی‌خواهند اما زمان/حافظه GitHub Actions محدود است.
- Artifact یک روز نگهداری می‌شود.
- ترجمه متون کلامی و سازگاری مدل مرد هنوز به آزمون عملی نیاز دارند.
- هر کلیپ مستقل است، بنابراین ممکن است یکی موفق و دیگری ناموفق باشد.

## عیب‌یابی
- در لاگ برنامه اصلی، Started per-clip Bengali artifact upload و سپس Triggered Bengali dubbing باید ثبت شود.
- اگر Bengali handoff FAILED دیده شد، آپلود یا dispatch شکست خورده است.
- در GitHub Actions / Didban Bengali Auto Dubbing خطای مدل، FFmpeg و ارسال بله مشخص می‌شود.
- در فایل تشخیصی delivery.json اطلاعات ارسال موفق ذخیره می‌شود.

## توقف اضطراری
در velayat-monitor.yml مقدار ENABLE_BN_DUB_INSTANT را false کنید؛ گزارش‌های اصلی و کلیپ فارسی مستقل باقی می‌مانند.
